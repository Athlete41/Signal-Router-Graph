# 信号路由图

## 框架要求

### 功能
1. 自带编辑器基本功能：重做、撤销、保存、另存为等  
2. 操作简洁  
3. 基本的鲁棒性：加载自定义图文件时不崩溃，日志系统提示兼容性问题  
4. 良好的日志系统：便于追踪错误和调试代码  

### 拓展性
1. 可重写连接事件
2. 渲染可修改
3. 可自定义序列化与反序列化，用于自定义写入和加载

### PyQt 相关约束

#### 连接依赖
- PyQt 5.15.9  
- 使用 `Auto` 或 `Queued` 类型连接。多线程情况下，必须先移动对象到线程再连接，才能保证信号投递到正确线程  
- 信号 `disconnect` 指定槽时，不会断开该槽的所有连接，而是一个一个断开，且遵循 **后进先出** 顺序  

#### 内存安全
**基本规则**  
1. 父对象移除时，所有子对象也会被移除  
2. 若对象间存在属性关系但没有父子关系，GC 计数器归零时可能在析构中被删除  

**由此延伸的约束**  
1. 虽可依赖 GC 规则删除，但不推荐依赖，因为不可靠且不细致。最好使用某种显式清除方法  
2. 若需在某个对象内部创建线程，最好提供全局方法进行注册管理，确保线程不会被析构删除

## 遇到的问题和解决方案

1. **粘贴后不触发连接的问题**  
   - 通过调试器发现是底层框架的问题，底层框架在粘贴后触发, 反序列使用的边是默认的 `Edge` 类, 而我们需要依赖自定义的 `MyEdge` 类,
   于是通过复制并修改粘贴板类来修复。

2. **连接类型一致性问题**
   - 我们希望用户能对连接类型进行配置，而不是默认使用 `Auto` 类型, 但由于上述的PyQt5.15.9中disconnect有后进先出的特性, 如果需要细致管理连接类型, 则需要额外添加更多复杂度。考虑到此项用处不大, 我决定使用一个全局参数, 所有连接采用同一种类型, 这样就不需要管理连接类型。

3. **多线程时连接时机问题**
    - 上述的PyQt5.15.9中特性且框架反序列化默认先初始化节点再连接, 所以开发者最好在节点初始化过程就完成线程创建和移动, 然后触发连接事件, 我打算在文档中说明这一点。

## 新框架的约束与方法

### 生命周期管理
- 节点对象提供的槽端口或信号端口可能并非对象本身所有，可能来自内部成员，而这些成员可能位于其他线程  
- 需要构建生命周期关系：使这些成员的生命周期相等  
- 外部默认判断信号或槽是否已销毁，是基于该对象进行判断  
- 销毁时需提供 `cleanup` 方法，**必须重写该方法以显式销毁**  

### 节点树
- 只使用第 0 列，其他列不用  
- 提供方法设置目录显示（图标、标题等）  
- 节点显示只需在定义类时重写特定类属性即可  
- 若节点显示配置与上述方法冲突，优先采用节点显示配置  
- **不允许两个节点拥有相同路径**，否则强制抛出异常  

### 反序列化约束
1. **节点路径不可随意修改**  
   图反序列化时依靠节点在节点树中的路径（元组类型）来定位节点。该路径不能随意修改，但节点类型可以自由更改。

2. **端口重连顺序依赖**  
   反序列化时端口的重连依赖于端口的声明顺序。若需要为类添加新端口，**建议在现有端口列表的末尾追加**，而不是在中间插入。在中间插入可能导致已保存的连接映射错位。
