# 协议解析器 V3 — 设计文档

## 一、概述

协议解析器 V3 是一个**协议解析节点**，职责是从 `QByteArray` 数据流中解析 V3 协议包，处理片段重组、CRC-16 校验、坏包→gap 转换，并按通道 ID 分发到对应输出端口。

**核心原则：** 脏活全包。示波器不碰协议解析，只收干净数据。

```
输入：QByteArray（来自信号发生器、串口、TCP 等）
输出：N 个静态端口，每个输出 (ndarray, gap_count, interval_us)
```

**多变体方案：** 按输出端口数拆为三个注册节点，每个节点有固定数量的输出端口，不支持运行时增减。

### 变体列表

| 变体 | tppath | 输出端口数×签名 | 接受 channel_id |
|------|--------|----------------|----------------|
| 协议解析器V3-1ch | `("数据处理", "协议解析器V3-1ch")` | 1 × (object, int, int) | 仅 0 |
| 协议解析器V3-2ch | `("数据处理", "协议解析器V3-2ch")` | 2 × (object, int, int) | 0~1 |
| 协议解析器V3-4ch | `("数据处理", "协议解析器V3-4ch")` | 4 × (object, int, int) | 0~3 |

### 端口约定

每个通道对应一个独立输出端口，端口 key 按通道编号命名：

| 变体 | 端口 keys | 信号签名 |
|------|-----------|---------|
| 1ch | `ch0` | `pyqtSignal(object, int, int)` |
| 2ch | `ch0`, `ch1` | 同上 |
| 4ch | `ch0`~`ch3` | 同上 |

信号参数：
- `object` — `numpy.ndarray(float64)`，含前部 NaN gap 标记
- `int` — gap_count，前 N 个点为危险区域
- `int` — interval_us，采样间隔微秒

## 二、架构

```
发送方线程 → emit → AutoConnection
  │
  ▼
_ProtocolParserWorker（独立 QThread）
  │ _buffer（bytearray 累积缓冲区）
  │ 1. 找 0xAA55 帧头
  │ 2. 读元数据 → 计算完整包长 (15+4N)
  │ 3. 等待完整包 / 检测下一帧头（拆包→gap）
  │ 4. decode_packet(qba) ← 复用 waveform_protocol_v3
  │ 5. emit op_signal(channel_id, data, gap, interval_us)
  │
  │ op_signal → AutoConnection
  ▼
ProtocolParserContent._onParsedData(ch, data, gap, interval_us)
  │
  ├─ channel_id 在范围内 → 对应静态端口 emit
  └─ channel_id 超出范围 → 日志警告，丢弃
```

**设计要点：**
- **独立 Worker 线程**：解析在工作线程运行，不阻塞主线程或发送方线程
- **复用协议层**：CRC-16 校验和字节解析委托给 `waveform_protocol_v3.decode_packet`，不手写
- **静态端口路由**：端口在 `__init__` 中一次性声明，不动态创建
- **内容部件透传**：收到 Worker 的数据后，按 channel_id 直接路由到对应的 `pyqtSignal` 属性

### 内容部件信号创建

内容部件根据 ch_count，在 `__init__` 中用 `setattr` 创建 N 个 `pyqtSignal(object, int, int)`，key 为 `ch0`~`chN-1`。

---

## 三、线程模型

- **专用 QThread**：一个解析器节点拥有一个独立工作线程
- `_ProtocolParserWorker` 在该线程中运行，负责接收数据、重组、校验、解码
- 对外暴露 `@pyqtSlot(QByteArray)` 的 `writeData` 方法，通过 Qt AutoConnection 跨线程接收输入
- `op_signal` 跨线程发送解析结果回主线程

Worker 接口：

```
_ProtocolParserWorker(QObject)
  ── op_signal(channel_id: int, data: ndarray, gap_count: int, interval_us: int)
  ── stats_signal(total_good: int, total_bad: int, bufsz: int)
  ── @pyqtSlot(QByteArray) writeData(qba)  → 将数据追加到缓冲区，触发处理
```

## 四、片段重组算法

### 核心循环

内部维护一个 `bytearray` 缓冲区，每次收到数据后执行：

```
while True:
  1. 查找 0xAA55 帧头，丢弃前面的垃圾字节
  2. 如果找不到帧头 → break 等待更多数据
  3. 读取 data_count（buf 偏移 7~8），计算完整包长 = 15 + 4×data_count
  4. 判断当前缓冲区完整性：
     a. 如果够一个完整包 → decode_packet 校验 + 解码
        - 成功 → emit 正常数据
        - 失败 → 整包变 gap 包（gap_count = data_count + 原始 gap）
     b. 如果不够 → 在预期长度范围内查找下一帧头
        - 找到下一帧头 → 当前包损坏，整包 gap，跳到下一帧头
        - 没找到 → break 等更多数据
  5. 前移指针到已处理包尾
```

**关键细节：** 使用读指针（read index）追踪位置，避免每次切片 `buf = buf[pkt_len:]` 导致 O(n²) 拷贝。仅在指针超出上限（1MB）时裁剪。

### 帧头查找

`_findHeader(buf, start, end)` — 在 `buf[start:end]` 中线性扫描 `0xAA 0x55`，找不到返回 -1。步长 1 字节，不可规避。

## 五、坏包→gap 规则

| 场景 | 触发条件 | 输出 | gap_count |
|------|----------|------|-----------|
| 校验通过 | CRC-16 匹配 | 正常解码分发 | 原始 gap_count |
| CRC-16 失败 | `decode_packet` 返回 None | 发射 gap 包，丢弃 | **data_count + gap_count** |
| 片段不完整 + 下一帧头已出现 | 预测长度内检测到 0xAA55 | 发射 gap 包，跳至下一帧头 | **data_count + gap_count** |
| 片段不完整 + 无下一帧头 | 缓冲区等待 | 无输出 | — |
| 帧头前垃圾数据 | 0xAA55 之前有字节 | 静默丢弃 | 不报告 |

**gap 包构造**：`np.full(data_count + gap_count, np.nan, dtype=np.float64)`，emit 时 gap_count = 原始 data_count + 原始 gap_count。

## 六、路由逻辑

`_onParsedData(channel_id, data_np, gap_count, interval_us)` 主线程槽函数：

1. 计算 `port_id = channel_id - channel_offset`
2. 如果 `port_id` 超出变体端口范围 → 日志警告，丢弃
3. 否则 → `getattr(self, f"ch{port_id}").emit(data_np, gap_count, interval_us)`

### 通道偏移 (Channel Offset)

QSpinBox 配置项，使解析器可以接收非零起始的 channel_id：

| 偏移值 | 端口 ch0 接收 | 端口 ch1 接收 | 端口 ch2 接收 | 端口 ch3 接收 |
|--------|--------------|--------------|--------------|--------------|
| 0（默认） | channel_id=0 | channel_id=1 | channel_id=2 | channel_id=3 |
| 2 | channel_id=2 | channel_id=3 | channel_id=4 | channel_id=5 |

## 九、边界条件

| 场景 | 处理 |
|------|------|
| 空输入 | 直接返回 |
| 全垃圾数据 | 持续扫描 0xAA55，累积在缓冲区 |
| 缓冲区无限增长 | 设 1MB 上限，超过时丢弃前半部分 |
| 包分多段到达 | 片段重组，补全后校验、分发 |
| 包损坏 + 下一包紧随 | 坏包→gap，跳至下一帧头 |
| 通道 ID 超出变体范围 | 日志警告，丢弃 |
| CRC 校验字节含 0xAA55 | 校验在包尾 2 字节，帧头只在包起始扫描，不干扰 |
| 多包拼接 | 逐个解析直到缓冲区耗尽 |

## 十、代码复用方案

三个变体通过**基类 + 子类**模式实现：

```
_ProtocolParserV3Base(ConnNode)        ← 共享 Worker、路由逻辑、序列化
  ├── ProtocolParserV3_1ch             ← CHANNEL_COUNT=1
  ├── ProtocolParserV3_2ch             ← CHANNEL_COUNT=2
  └── ProtocolParserV3_4ch             ← CHANNEL_COUNT=4
```

基类根据 `CHANNEL_COUNT` 动态生成 `signalsConf` 和 `registerSignal` 调用。内容部件接受 `ch_count` 参数。Worker 完全复用。

## 十一、验证清单

- [ ] 完整单包解析正确（数据值、channel_id、interval_us、gap_count 全部匹配）
- [ ] 包分多段到达 → 补全后正确解析
- [ ] 包损坏 → 下一帧头已出现 → 跳帧并报告 gap
- [ ] 包损坏 → 无下一帧头 → 等待补齐
- [ ] CRC-16 校验失败 → 整包变 gap
- [ ] 垃圾数据在帧头前 → 静默丢弃
- [ ] 多个包拼接 → 逐个解析
- [ ] 通道 ID 在变体范围内 → 对应端口 emit；超出 → 静默丢弃
- [ ] 1ch / 2ch / 4ch 变体正确工作
- [ ] 通道偏移配置生效
- [ ] 调试日志可开关，关闭后无日志输出

## 十二、优化方向

核心性能路径是 `_processBuffer()` 循环，注意以下优化点：

| 优化点 | 方案 |
|--------|------|
| 缓冲区切片 | 使用 read index 指针追踪位置，避免 `buf = buf[pkt_len:]` O(n²) 拷贝 |
| stats 信号频率 | ≥100ms 限频 emit，中间仅更新本地计数器 |
| QByteArray 构造 | `decode_packet` 接收 `bytes`，减少一次包装 |
| numpy 分配 | 对固定包大小可预分配 ndarray 池（暂缓，实测瓶颈再优化） |
