# 示波器节点 (OscilloscopeNode) 设计文档

## 一、概述

示波器节点是信号路由图编辑器中的可视化节点，接收二进制协议编码的波形数据（`QByteArray`），在工作线程中解析、缓存、处理，并实时绘制波形曲线。

**类似真实示波器**的功能：
- 显示实时波形曲线
- 时间窗口调节（水平缩放）
- 放大倍数 / 偏移调节（垂直缩放）
- 历史回看（滚动条）
- 缓冲区覆盖标记（红色垂直线）

## 二、架构

```
┌─────────────────────────────────────────────────────┐
│                   主线程 (GUI)                       │
│  ┌───────────────────────────────────────────────┐  │
│  │ OscilloscopeContent                           │  │
│  │  ├── History RingBuffer (滚动历史)             │  │
│  │  ├── WaveformWidget  (QPainter 波形绘制)       │  │
│  │  ├── QScrollBar      (水平滚动)                │  │
│  │  ├── 采集系统 GroupBox  (FPS, Temp, Buffer)   │  │
│  │  ├── 水平系统 GroupBox  (时间窗口, 时间/格)    │  │
│  │  ├── 垂直系统 GroupBox  (放大倍数, 偏移)       │  │
│  │  └── 操作栏          (Start, 清空, 丢点/覆盖)  │  │
│  └────────────────┬─────────────────────────────┘  │
│                   │ ▲ 信号/槽 (跨线程 AutoConnect)  │
│                   │ │                               │
│                   ▼ │                               │
│  ┌─────────────────────────────────────────────┐   │
│  │ _Worker (QObject, 在工作线程中)              │   │
│  │  └── OscilloscopeSampler                    │   │
│  │       ├── Temp RingBuffer (帧间缓存)         │   │
│  │       ├── QTimer (帧定时器)                  │   │
│  │       └── 帧刷新逻辑                        │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

### 2.1 线程模型

采用标准的 `_Worker + QThread` 模式：

1. `initUI()` 中创建 `_Worker` 对象和 `QThread`
2. 启动线程，用 `BlockingQueuedConnection` 调用 `initSampler()` 在工作线程创建 `OscilloscopeSampler`
3. 所有后续通信通过 PyQt5 信号-槽跨线程投递（`AutoConnection`，Qt 自动识别跨线程→异步投递）

### 2.2 渲染握手

```
工作线程                       主线程
   │                            │
   │  frameReady(data, ...) ──▶ │  _onFrameReady()
   │                            │    ├── WaveformWidget.setData()
   │                            │    ├── 更新滚动条
   │                            │    ├── 更新时间/格显示
   │                            │    ├── 更新覆盖计数
   │                            │    ├── repaint()
   │                            │    └── renderComplete.emit()
   │  ◀───────────────────────── │
   │  onRenderComplete()         │
   │     _awaiting_render = False│
   │     继续下一帧              │
```

核心目的：**防止工作线程的帧率超过主线程的渲染能力**。工作线程发射 `frameReady` 后设置 `_awaiting_render = True`，阻塞后续帧的发射，直到主线程完成渲染并回复 `renderComplete`。

## 三、环形缓冲区 (RingBuffer)

示波器使用 **两个独立** 的 RingBuffer，分别在工作线程和主线程：

| 缓冲区 | 位置 | 用途 | 默认容量 | UI 可调 |
|--------|------|------|----------|---------|
| Temp RingBuffer | `OscilloscopeSampler`（工作线程） | 帧间累积数据源协议包 | 5000 | ✅ Temp |
| History RingBuffer | `OscilloscopeContent`（主线程） | 滚动历史数据，支持回看 | 1000 | ✅ Buffer |

### 3.1 原理

定长数组 + 循环写入指针，当数据超出容量时自动覆盖最旧数据，并**记录覆盖次数**（`_overwrite_count`）。

```
写入方向 →      write_idx
┌──┬──┬──┬──┬──┬──┬──┬──┐
│D5│D6│D7│D8│D1│D2│D3│D4│
└──┴──┴──┴──┴──┴──┴──┴──┘
              ↑           ↑
              最旧数据    最新数据
```

- `capacity`：固定容量（用户可调，默认 1000）
- `write_idx`：当前写入位置
- `count`：有效数据数（`< capacity` 时还在填充阶段）
- `_overwrite_positions`：自上次读取以来被覆盖的位置索引列表
- `_overwrite_count`：自启动以来总覆盖次数

### 3.2 可见窗口计算

```
时间窗口 (如1s)
┌────────────────────────────┐
│   可见数据 (visible_count)  │
├────────────────────────────┤
│◀─── scroll_offset ────────▶│
└────────────────────────────┘
←─── 全部数据 (total) ──────→
```

- `visible_count = time_window_s × 1_000_000 / sampling_interval_us`
- `scrollbar_max = total - visible_count`
- `scroll_offset = scrollbar_max - scrollbar_value`（scrollbar 最右=最新数据）

### 3.3 覆盖标记与 Gap（危险区域）

示波器有两种不同的"数据不可信"标记：

| 类型 | 来源 | 触发条件 | 显示效果 |
|------|------|----------|----------|
| **History 覆盖** | History RingBuffer（主线程） | 历史数据被新数据覆盖 | 红色垂直线标记覆盖边界 |
| **Temp Gap (丢点)** | Temp RingBuffer（工作线程） | 帧间缓存溢出，数据丢弃 | 红色背景 + 红色边界线 + NaN 0V 段 |

**Gap 数据流**：

1. Temp RingBuffer 溢出 → `overwrite_count` 增加
2. `_flushBuffer()` 在数据前插入 `gap_count` 个 `NaN` 魔法数字
3. 主线程剥离 NaN 存入 History RingBuffer（避免污染历史数据）
4. 渲染时重新插入 NaN → `WaveformWidget` 检测到 `NaN` 视为 0V
5. 危险区域背景 + 红色边界线 + 绿色波形在 0V 穿过

**关键设计**：gap 信息通过 `NaN` 魔法数字编码在数据数组中，不依赖携带额外参数。`float('nan')` 是 IEEE 754 标准 sentinel，`math.isnan()` 检测极快，不可能与有效数据值冲突。

## 四、协议格式 (waveform_protocol)

示波器和信号发生器之间通过 `connnodes/waveform_protocol.py` 定义的二进制协议通信：

### v2 格式（当前）

```
| 帧头 2B | 采样间隔 4B | 数据数 2B | 起始丢弃数 2B | float32 数组 N×4B | 校验 1B |
| 0xAA55  | uint32 LE   | uint16 LE | uint16 LE     | float32 LE        | XOR     |
```

- **帧头**：`0xAA 0x55`，用于同步识别
- **采样间隔**：微秒（μs），每个数据点之间的时间间隔
- **数据数**：本次包携带的总浮点数数量（含 gap 点 + 有效数据）
- **起始丢弃数**（v2 新增）：数据载荷前 N 个点为不可信丢弃点（危险区域/NaN 魔法数字）
- **数据**：float32 数组（小端序），前 gap_count 个为 `NaN` 魔法数字
- **校验**：XOR，从帧头到最后一个数据字节

> **v1→v2 变更**：偏移 8 新增 `起始丢弃数` 字段（2B），数据载荷偏移从 8 变为 10。最小包长度从 9 变为 11。

```python
# 编码示例（信号发生器侧，无 gap）
from connnodes.waveform_protocol import encode_packet
qba = encode_packet(interval_us=1000, data=[1.0, 2.0, 3.0, ...])

# 编码示例（带 gap 标记）
qba = encode_packet(interval_us=1000, data=[1.0, 2.0, 3.0],
                    gap_count=5)  # 前 5 个点编码为 NaN

# 解码示例（示波器侧）
from connnodes.waveform_protocol import decode_packet
result = decode_packet(qba)
# → {"sampling_interval_us": 1000, "data": [float, ...], "gap_count": int}
```

## 五、UI 布局

示波器节点的 UI 分为五个区域：

### 5.1 波形画布 (WaveformWidget)

自定义 `QWidget`，用 `QPainter` 绘制：
- 黑色背景
- 暗色网格线（水平 × 垂直，5 格）
- 绿色波形曲线（NaN 魔法数字点视为 0V，与其他点连续绘制）
- 红色危险区域背景 + 红色边界线（数据前部 gap 丢点区域）
- 红色垂直线标记历史 RingBuffer 覆盖边界
- 底部时间轴标签（负值表示距当前的时间）
- 右上角显示每格时间（μs/div / ms/div / s/div）和电压/格

### 5.2 采集系统

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| FPS | 1–120 | 30 | 帧定时器频率（每秒发射多少帧到主线程） |
| Temp | 100–50000 | 5000 | 工作线程临时缓冲区容量（溢出产生 gap 丢点） |
| Buffer | 100–100000 | 1000 | 主线程历史环形缓冲区容量 |

### 5.3 水平系统（时间轴）

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|

### 5.4 垂直系统（幅值轴）

### 5.5 操作栏

## 六、关键参数详解

### 6.1 FPS（帧率）

控制工作线程每秒向主线程发送多少帧数据。**不是采样率**，采样率由数据源（信号发生器、串口等）决定。

- 高 FPS → 画面更新更流畅，但 CPU 消耗更高
- 低 FPS → CPU 节省，但画面更新有延迟感
- 推荐值：30（平衡流畅度和性能）

### 6.2 Buffer（缓冲区容量）

环形缓冲区的最大点数。

- 容量太小 → 数据快速被覆盖（红色标记频繁出现）
- 容量太大 → 内存占用高，滚动条范围大
- 选型参考：`buffer_size × 采样间隔 × 4bytes` ≈ 内存占用
- 例如：采样间隔 1ms，buffer=10000 → 显示 10 秒数据 → 内存 ~40KB

### 6.3 时间窗口

画布上同时显示的时间跨度。如果时间窗口内包含的数据点超过缓冲区容量，会自动限制为缓冲区大小。

- 短窗口 → 显示更多细节（放大）
- 长窗口 → 显示更长时间范围（缩小）

### 6.4 放大倍数 / 偏移

- **放大倍数**：对每个数据点 `value * amplification`，用于放大微小信号
- **偏移**：对每个数据点 `value + offset`，用于上下平移波形

公式：`display_value = original_value × amplification + offset`

## 七、数据流（完整路径）

### 双层缓冲区架构

示波器使用 **双层环形缓冲区** 隔离工作线程和主线程：

| 缓冲区 | 位置 | 用途 | 容量 |
|--------|------|------|------|
| Temp RingBuffer | 工作线程 (`OscilloscopeSampler`) | 帧间缓存，累积数据源协议包 | 5000 点（UI 可调） |
| History RingBuffer | 主线程 (`OscilloscopeContent`) | 滚动历史数据，支持回看 | 1000 点（UI 可调） |

Temp 缓存溢出时产生 gap——丢失的数据点在波形左边缘用 `NaN` 魔法数字标记为红色危险区域。

```
信号发生器 / TCP / 串口等数据源
  │
  │ QByteArray (waveform_protocol v2 编码，gap_count=0)
  ▼
OscilloscopeNode.inputs[0] (协议数据端口)
  │
  │ registerSlot → writeData (跨线程 AutoConnection)
  ▼
OscilloscopeSampler.writeData(qba)
  │ decode_packet(qba)  →  {sampling_interval_us, data, gap_count}
  │ 剥离前部 gap_count 个 NaN → clean_data
  │ Temp RingBuffer.write_batch(clean_data)
  ▼
QTimer 帧定时器 (每秒 FPS 次)
  │ _flushBuffer():
  │   Temp RingBuffer.read_frame() → data, gap_count
  │   如果 gap_count > 0: data = [NaN] * gap_count + data
  ▼
frameReady.emit(data_with_nan, gap_count, sampling_interval_us)
  │ (跨线程 AutoConnection)
  ▼
OscilloscopeContent._onFrameReady()
  │ 剥离前部 gap_count 个 NaN → clean_data
  │ History RingBuffer.write_batch(clean_data)
  │ _render_frame():
  │   从 History RingBuffer 读取可见窗口数据
  │   如果 _pending_gap_count > 0:
  │     data = [NaN] * gap + data
  │   WaveformWidget.setData(data_with_nan, ...)
  │ 更新 UI 控件
  │ renderComplete.emit()
  ▼
OscilloscopeSampler.onRenderComplete()
  │ _awaiting_render = False
  → 下一帧 tick 可继续发射
```

## 八、典型使用场景

### 8.1 信号发生器 → 示波器

```
[信号发生器] ──(QByteArray)──▶ [示波器]
```

- 信号发生器以固定频率生成波形数据（正弦波/方波/三角波/锯齿波）
- 编码为 waveform_protocol 后通过边发送到示波器
- 示波器解析、缓存、显示
- 最简单的测试方案

### 8.2 TCP 数据源 → 示波器

```
[TCP 服务端] ──(QByteArray)──▶ [示波器]
```

- 外部设备通过 TCP 发送符合 waveform_protocol 的数据
- TCP 服务端接收后通过边转发到示波器
- 适用于远程数据采集

### 8.3 串口数据源 → 示波器

```
[串口设备] ──(QByteArray)──▶ [示波器]
```

- 串口设备发送符合 waveform_protocol 的二进制数据
- 适用于嵌入式设备数据监控

## 十、性能考量

| 关注点 | 说明 |
|---|---|
| **帧率 vs 渲染** | 渲染握手确保主线程不被工作线程的帧率压垮 |
| **缓冲区大小** | 容量过大会增加 read_frame 和 scrollbar_max 计算开销 |
| **波形绘制** | QPainterPath 在大数据量（>10万点）时可能卡顿 |
| **跨线程通信** | 所有跨线程信号使用 AutoConnection，Qt 自动异步投递 |
| **覆盖标记** | 每帧读取后清空 `_overwrite_positions`，避免累积膨胀 |

## 十一、常见问题

### Q: 波形不动了？
A: 检查是否已点击 **Start**（按钮应显示 "Stop"），检查数据源节点是否正在发送数据。

### Q: 滚动条拖不动，总是自动弹回最右边？
A: 这是"自动跟踪最新数据"模式。如果滚动条在最右端（最大值），新数据到来时会自动跟进。要查看历史数据，向左拖动滚动条即可。

### Q: 红色垂直线是什么意思？
A: 红色垂直线标记了**历史 RingBuffer 覆盖区域**的边界。当历史缓冲区的数据写入速度超过容量时，旧数据被覆盖。两条红线之间的数据**已被覆盖一部分**，不能完整信任。增大 Buffer 参数可以减少覆盖。

### Q: 波形左边缘的红色背景 + 红色竖线是什么？
A: 这是 **Temp 缓存丢点（Gap）** 标记。当工作线程的临时缓存（Temp）溢出时，无法缓存的数据点被丢弃。红色背景区域表示数据**不连续**——有 N 个数据点在帧间丢失。红色边界线标记丢点区域的左右边界，绿色波形在丢点区域视为 0V。增大 Temp 参数可以减少丢点。

### Q: Temp 和 Buffer 有什么区别？
A: **Temp** 是工作线程的帧间缓存（默认 5000），数据源到工作线程之间的临时存储，溢出产生 gap。**Buffer** 是主线程的历史缓存（默认 1000），控制显示滚动范围，溢出产生覆盖标记。两者独立工作。如果 Temp 太小而数据源速度快，会产生大量丢点；如果 Buffer 太小，历史数据很快被覆盖。

### Q: 波形显示"断裂"或只显示部分？
A: 检查时间窗口设置是否合适。如果窗口太小，只能看到少量数据点；如果窗口太大，数据点过于密集。

### Q: 画面更新卡顿？
A: 降低 FPS（尝试 15 或更低），或减少缓冲区容量。如果数据点数很大（>100k），波形绘制本身也会变慢。
